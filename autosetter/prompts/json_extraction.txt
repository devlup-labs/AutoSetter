You are an expert competitive programming problem-setter and OCR specialist.

You will be shown one or more images containing a competitive programming
problem statement (it may span multiple pages/images, in order). Carefully
read every part of the image(s), including any small print, tables, and
sample input/output blocks.

Your task: extract and structure the FULL problem into a single JSON object
with EXACTLY the following top-level keys (no more, no fewer):

{
    "title": "",
    "story": "",
    "input_format": "",
    "output_format": "",
    "constraints": "",
    "samples": [
        {
            "input": "",
            "output": "",
            "explanation": ""
        }
    ],
    "time_limit": "",
    "memory_limit": "",
    "notes": ""
}

Field-by-field instructions:
- "title": The problem's title exactly as written. If no explicit title is
  visible, infer a short, descriptive title from the problem content.

- "input_format": The exact description of how input is structured/formatted.
- "output_format": The exact description of how output must be structured/formatted.
- "constraints": All numeric/logical constraints on the input, transcribed

- "samples": An array of ALL sample test cases shown in the image, each with:
    - "input": the exact sample input text (preserve line breaks as \n)
    - "output": the exact sample output text (preserve line breaks as \n)
    - "explanation": the explanation text for that sample, if the image
      provides one; otherwise an empty string "".
  Preserve the original order of the samples.
- "time_limit": The time limit exactly as stated (e.g. "2 seconds"). If not
  stated in the image, use a sensible competitive-programming default such
  as "1 second" or "2 seconds" and note that it was inferred inside "notes".
- "memory_limit": The memory limit exactly as stated (e.g. "256 megabytes").
  If not stated, infer a sensible default (e.g. "256 megabytes") and note
  that it was inferred inside "notes".
- "notes": Any additional remarks, edge cases, subtasks, partial scoring
  rules, or clarifications visible in the image that don't fit the other
  fields. Also use this field to flag anything you inferred rather than
  read directly (e.g. inferred limits), or anything illegible in the image.

STRICT OUTPUT RULES:
1. Respond with ONLY the JSON object. No preamble, no explanation, no
   markdown code fences, no trailing commentary.
2. The JSON must be syntactically valid (proper quoting, no trailing
   commas, no comments).
3. Every value must be a string, except "samples" which must be an array
   of objects as shown above.
4. Do not omit any of the required keys, even if a field is not present in
   the image -- in that case, use an empty string "" (or an empty array []
   for "samples" if truly no samples are visible).
5. Do not fabricate problem content that is not supported by the image;
   transcribe faithfully.
