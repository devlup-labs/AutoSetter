# PHASE 2 — CLASSIFY THE CHECKING STRATEGY

For every output element, determine its validation category.

Use the following decision procedure.

### CASE A — Exact string or word comparison

Use this strategy when the output item is:

* A word.
* A string.
* A symbolic token.
* A categorical answer.
* Any single-token textual value requiring exact equality.

Generate:

string actual = ouf.readToken();

if (expected != actual) {
quitf(_wa, "Expected '%s', but found '%s'",
expected.c_str(), actual.c_str());
}

Do not perform case normalization unless the JSON explicitly requires it.

Do not trim, reinterpret, or approximate string values unless explicitly specified.

---

### CASE B — Integer or 64-bit integer comparison

Use this strategy when the output item is:

* An integer.
* A long integer.
* A 64-bit number.
* A count.
* An index.
* A discrete numeric result requiring exact equality.

Generate:

long long expected = ans.readLong();
long long actual = ouf.readLong();

if (expected != actual) {
quitf(_wa, "Expected %lld, but found %lld",
expected, actual);
}

Use exact comparison.

Do not use floating-point comparison for integer values.

---

### CASE C — Floating-point comparison

Use this strategy when the output item is:

* A decimal number.
* A real number.
* A floating-point result.
* A numerical approximation.

Generate:

double expected = ans.readDouble();
double actual = ouf.readDouble();

if (!doubleCompare(expected, actual, 1e-6)) {
quitf(_wa, "Expected %.9f, but found %.9f",
expected, actual);
}

Use tolerance `1e-6` unless the JSON explicitly specifies another comparison tolerance.

Do not use exact equality for floating-point values.

---

### CASE D — Multiple output elements

If the output contains multiple values:

1. Determine the exact sequence from `output_format`.
2. Process values in that sequence.
3. Apply the appropriate checking strategy independently to each value.
4. Stop immediately and return `_wa` when the first invalid value is found.
5. Continue only when the current value passes validation.

The generated checker must preserve the output ordering defined by the JSON.

Do not reorder values.

Do not skip values.
